## 第 1 章 这套软件是什么（先看懂再动手）

### 1.1 一句话介绍

这是一套**小说采集与发布系统**：你在后台配置「采集规则」（去哪个网站、怎么找书）和「采集任务」（什么时候抓、抓多少），系统自动把小说抓回来、清洗净化、存进数据库；前台就是一个漂亮的小说站（书城 / 详情页 / 阅读页 / 搜索），读者直接访问阅读。

### 1.2 整体架构（一张图看懂）

```
        读者的浏览器                     你的服务器（一台 2核4G 云主机即可）
      ┌────────────┐                 ┌─────────────────────────────────────┐
      │ 书城/阅读页 │ ──── HTTP ────► │  Next.js 主应用   http://IP:3000     │
      └────────────┘                 │  ├─ 前台站点  /?view=home（多主题）   │
                                     │  ├─ 后台管理  /（密码登录）           │
      管理员的浏览器                   │  ├─ 采集引擎（抓取→解析→清洗→入库）   │
      ┌────────────┐                 │  └─ SQLite 数据库  db/custom.db      │
      │ 规则/任务/  │ ──── HTTP ────► │        ▲ 127.0.0.1 直连             │
      │ 书籍/设置  │                 │  mini-services  端口 3010~3017       │
      └────────────┘                 │  （签名/解密/中继/隐身渲染等 8 个小服务）│
                                     └──────────────────┬──────────────────┘
                                                        ▼  按规则抓取（可经出口代理）
                                              目标小说站点（公网）
```

读法：浏览器只跟 **3000 端口**的主应用打交道；主应用需要"特殊站点的签名 / 解密 / 隐身渲染"时，才去叫同一台机器上 **3010~3017** 端口的小服务帮忙；所有抓取动作最终都发生在主应用与目标网站之间。

### 1.3 文件夹长什么样（拿到代码后）

```
novel-system/                 ← 项目根目录（本教程里叫它"项目目录"）
├── src/                      ← 源代码（Next.js 应用 + 采集引擎）
├── mini-services/            ← 8 个采集支撑服务（端口 3010~3017，第 8 章细讲）
├── prisma/schema.prisma      ← 数据库表结构定义
├── db/custom.db              ← SQLite 数据库文件（初始化后生成，★备份它）
├── data/                     ← 采集产物（封面 covers/ / TXT 下载 downloads/）
├── .env                      ← 你的配置文件（第 4 章从模板复制而来）
├── .env.example              ← 配置模板（每个变量都带中文注释）
├── package.json              ← 项目命令清单（bun install / bun run build 都在这定义）
├── .zscripts/dev.sh          ← 开发试用一键启动脚本
├── install.sh                ← Docker 一键安装脚本
├── docker-compose.yml        ← Docker 部署编排
└── docs/INSTALL-GUIDE.md     ← 本教程
```

### 1.4 功能清单（这台机器都会干什么）

| 功能 | 说明 |
| --- | --- |
| **采集规则引擎** | 规则四段（列表页 / 书籍页 / 目录页 / 正文页）配 CSS 选择器或正则，可视化编辑 + 在线测试；`{page}` 占位符自动翻页 |
| **内置规则库（25 条）** | 随代码附带 25 条实测站点规则（77读书 / 番茄 / 七猫 / 得奇 / 笔趣阁系 / 起点中文 / 霹雳书屋 / 努努书坊 / 知轩藏书 / WuxiaWorld……），一键导入即用 |
| **多引擎反反爬降级链** | native HTTP（curl 链）→ 出口代理池轮换 → bun 中继桥(3011) → Scrapling 隐身桥(3012) → Obscura 本地 chromium 反检测渲染，按站点防护强度自动降级；另有独立反检测浏览器 cloak-browser(3016) 作可选增强 |
| **规则级出口代理池** | 对"只认国内 IP"的站点（如 77读书），给单条规则配 http/socks5h 代理，逗号分隔多条轮换（≤10 条） |
| **站级签名/解密代理** | token / 签名 / AES 类站点由 3010~3017 小服务承载，引擎自动对接 |
| **自动填充** | Docker 一键安装默认开：装完自动导入 7 条规则并开跑任务，约 20~40 分钟前台有书，之后每 30 分钟自动增量续采（可关） |
| **前台多主题站群** | **8 配色 × 8 风格 × 8 布局 = 512 套组合主题 + 9 套精选**（含笔趣阁经典 / 霹雳书屋仿站 / 久久小说仿站），浏览器里点选预览 |
| **伪静态 URL（6 预设）** | 书籍页/阅读页网址可在 动态查询 / 纯数字 / 字母+数字 / 目录式 / 无后缀 / 紧凑双段 之间一键切换，旧链接宽容解析**永不断链** |
| **自动 TDK（SEO）** | 每个前台页面自动生成 标题/描述/关键词 + canonical + JSON-LD；站点级 TDK 一键生成 |
| **屏蔽词过滤** | 内置屏蔽词（敏感词）系统，对采集入库内容做屏蔽词过滤，降低违禁内容风险（本轮新增功能） |
| **TXT 下载** | 后台把任意书籍合成带站点信息的 TXT 成品，读者可下载 |
| **数据备份/恢复** | 后台「数据备份」页一键导出/导入 JSON；停服后直接拷 `db/`、`data/` 目录亦可 |
| **仪表盘与体检** | 统计看板（卡片可开关）、服务健康灯、SEO 体检、规则极限校准 |

### 1.5 装完你会得到两个网址

| 地址 | 是什么 |
| --- | --- |
| `http://服务器IP:3000/` | **后台管理**（配规则、建任务、管书籍，需要密码登录） |
| `http://服务器IP:3000/?view=home` | **前台站点**（书城/详情/阅读页，读者看的，无需登录） |

## 第 2 章 准备服务器并安装 Bun

### 2.1 服务器要什么配置

| 项目 | 建议 | 说明 |
| --- | --- | --- |
| CPU | 2 核 | — |
| 内存 | **4 GB（最低 2 GB）** | 日常运行很省内存；但"生产构建"阶段峰值超 2 GB，2 GB 机器会被系统杀掉（见 [FAQ #10](#10-构建或安装中途日志出现-killed)）。2 GB 用户请走 Docker 路径或加 swap |
| 磁盘 | 10 GB 以上 | 代码 + 依赖约 1~2 GB，其余是数据库与封面/TXT 产物 |
| 系统 | **Ubuntu 22.04 / Debian 12**（推荐） | 其他主流 Linux 也可；Windows/Mac 想本地试玩见文末提示 |
| 网络 | 能上网 | 国内服务器下载 Bun/GitHub 仓库慢时：见本章 ✖ 报错对照表（重试 / 加速前缀 / zip 兜底） |

> 💡 还没买服务器？怎么买、怎么备案不在本教程范围。只提醒一句：**国内云服务器请到厂商控制台"安全组/防火墙"放行 3000 端口**（第 7 章访问要用）。

### 2.2 认识终端：所有命令都在这里敲

在你**自己的电脑**上打开一个终端窗口，用 ssh 连上服务器，之后所有命令都在这个窗口里输入：

**① 打开终端**

- Windows 10/11：开始菜单输入 `PowerShell`，回车（系统自带 ssh）。
- Mac：启动台 → 其他 → 终端（Terminal）。

**② 连接服务器**（把 `服务器IP` 换成你的真实 IP）：

▶ 执行：

```bash
ssh root@服务器IP
```

✔ 你会看到（第一次连接时）：

```text
The authenticity of host '1.2.3.4' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

手动输入 `yes` 回车，然后输入密码——**输入时屏幕不显示任何字符是正常的安全设计**，盲打完回车。看到命令行开头变成 `root@服务器:~#` 就连上了。

✖ 常见报错：

| 报错关键字 | 原因 | 解法 |
| --- | --- | --- |
| `Connection refused` / 长时间卡住 | 服务器 22 端口没放行 | 云控制台"安全组"放行 TCP 22 |
| `Permission denied` | 密码错，或厂商只给密钥登录 | 密码重试；密钥登录用 `ssh -i 密钥文件 root@IP` |

### 2.3 安装 Bun（本系统的运行引擎）

Bun 是类似 Node.js 的 JavaScript 运行工具，本项目用它装依赖、建数据库、启动服务。**一条命令安装**：

▶ 执行：

```bash
curl -fsSL https://bun.sh/install | bash
```

✔ 你会看到（末尾几行，示意）：

```text
######################################################################## 100.0%
bun was installed successfully!

To get started, run:

  source /root/.bashrc
  bun --version
```

按提示让新工具生效并验证（第二条约 1 秒，属正常）：

▶ 执行：

```bash
source ~/.bashrc
bun --version
```

✔ 你会看到：

```text
1.3.x
```

✖ 常见报错：

| 报错关键字 | 原因 | 解法 |
| --- | --- | --- |
| `curl: command not found` | 系统太干净没装 curl | `sudo apt update && sudo apt install -y curl` 后重跑 |
| 装完 `bun: command not found` | 当前窗口没加载新 PATH | 关掉窗口重新 ssh 登录；或重跑上面的 `source ~/.bashrc` |
| 下载卡住 / 超时 | 国内访问 bun.sh 不稳 | 重试几次；或先 `npm config` 无关——直接改用官网备用地址重试，仍不行可临时给终端挂代理再装 |

> 💡 **Docker 路线可以不装 Bun**：如果你打算全程用第 6 章的 Docker 方式部署，服务器上只需要 Docker（`bash install.sh` 会自动装），Bun 只在"本机直跑"路线（第 6 章 6.1/6.2）中必需。

## 第 3 章 把代码拿到服务器上

### 3.1 方式一：git clone（推荐）

▶ 在服务器上执行：

```bash
git clone https://github.com/u4399com-beep/heis.git novel-system
cd novel-system
```

✔ 你会看到（进度条走完，示意）：

```text
Cloning into 'novel-system'...
remote: Enumerating objects: 12345, done.
Receiving objects: 100% (12345/12345), 8.90 MiB | 2.30 MiB/s, done.
```

之后**本教程所有命令都在 `novel-system` 目录里执行**（命令行开头是 `root@服务器:~/novel-system#`）。

✖ 常见报错：

| 报错关键字 | 原因 | 解法 |
| --- | --- | --- |
| `git: command not found` | 服务器没装 git | `sudo apt update && sudo apt install -y git`（Ubuntu/Debian）后重跑 |
| 克隆卡住 / `Connection timed out` | 国内直连 GitHub 不稳 | 重试几次；或用加速前缀：`git clone https://ghfast.top/https://github.com/u4399com-beep/heis.git novel-system`；或改用方式二 |

### 3.2 方式二：上传压缩包（不用 git）

在你自己电脑的浏览器打开 `https://github.com/u4399com-beep/heis/archive/refs/heads/main.zip` 下载压缩包，用你顺手的工具（宝塔面板"上传"、`scp`、WinSCP 拖拽均可）传到服务器，然后解压并进入目录：

▶ 在服务器上执行（假设压缩包传到了 `/root`）：

```bash
cd /root
apt install -y unzip   # 没装 unzip 的话先装
unzip main.zip
cd heis-main
```

> 💡 两种方式二选一即可，得到的目录内容完全一样。下文统一用"项目目录"称呼它。

## 第 4 章 配置 .env（系统的"设置文件"）

`.env` 是系统的环境配置文件：数据库放哪、后台密码是多少，都写在这里。项目自带了一份带完整中文注释的模板，复制一份即可：

▶ 在项目目录执行：

```bash
cp .env.example .env
```

✔ 你会看到：命令成功时**没有任何输出**（Linux 的好习惯：没消息就是好消息）。

### 4.1 编辑 .env

用 `nano` 打开（服务器自带的小编辑器）：

▶ 执行：

```bash
nano .env
```

nano 用法三句话：**方向键移动光标 → 直接打字修改 → `Ctrl+O` 回车保存，`Ctrl+X` 退出**。

### 4.2 必须认识的三行（新手改这几行就够了）

打开后你会看到很多以 `#` 开头的注释行（# 开头的行只是说明，不生效）。重点看这三行：

```dotenv
DATABASE_URL=file:./db/custom.db

ADMIN_PASSWORD=audit-fix-2025
SESSION_SECRET=
```

| 变量 | 填什么 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | 保持默认 `file:./db/custom.db` | SQLite 数据库文件的位置（项目目录下 `db/custom.db`）。**不用改** |
| `ADMIN_PASSWORD` | **改成你自己的强密码** | 后台登录密码。默认值 `audit-fix-2025` 是公开的，**装完必须改**（第 7 章有警告框） |
| `SESSION_SECRET` | 随便一串长随机字符 | 登录会话的签名密钥。生产建议设置，例如 `SESSION_SECRET=zk83nfa7s2kdfh93hssd` 这类长串 |

改完的样子（示意）：

```dotenv
ADMIN_PASSWORD=我的强密码Example9X
SESSION_SECRET=xk72nfd93hsa8df72nsd9f
```

✖ 常见报错：

| 症状 | 原因 | 解法 |
| --- | --- | --- |
| 第 5 章 `bun run db:push` 报 `Environment variables loaded from .env` 之外还有 `File not found` | 没在项目目录里执行，或 `.env` 文件名打错（注意开头有个点） | `cd ~/novel-system` 后重新 `cp .env.example .env`；`ls -a` 能看到 `.env` 才对 |
| 密码里用了 `#` 或空格导致解析异常 | 特殊字符被当成注释/分隔 | 密码用纯字母+数字组合最省心 |

> 💡 其余以 `#` 注释掉的变量（采集引擎开关、桥地址、代理凭证等）都是**可选高级项**，不设置就自动回落安全默认值，新手不用动。全部变量的权威注释见 `.env.example` 文件本身，速查表见 [DEPLOY.md](../DEPLOY.md)「二·六、环境变量速查」。

## 第 5 章 安装依赖并初始化数据库

### 5.1 安装依赖（bun install）

▶ 在项目目录执行：

```bash
bun install
```

✔ 你会看到（几十秒到几分钟，示意）：

```text
bun install v1.3.x (hash)
Resolving dependencies
Checked 57 installs across 512 packages (no changes)
N packages installed
```

✖ 常见报错：

| 报错关键字 | 原因 | 解法 |
| --- | --- | --- |
| `bun: command not found` | 第 2 章的 Bun 没装好或没生效 | 重开终端窗口重新 ssh；或重跑 `source ~/.bashrc` |
| 网络超时 / `ENOTFOUND` | 国内访问 npm 官方源不稳 | 重跑一次（bun 有断点缓存）；或挂终端代理后再跑 |

### 5.2 初始化数据库（bun run db:push）

这一步按 `prisma/schema.prisma` 里定义的表结构，在你的 SQLite 文件里把所有表建好：

▶ 执行：

```bash
bun run db:push
```

✔ 你会看到（示意）：

```text
Environment variables loaded from .env
Prisma schema loaded from prisma/schema.prisma
Datasource "db": SQLite database "custom.db" at "file:./db/custom.db"

✔ Generated Prisma Client (v6.x.x) to ./node_modules/@prisma/client in xxx ms

Your database is now in sync with your schema. Done in xxx ms
```

看到 `Your database is now in sync` 就是建表成功。项目目录里会多出 `db/custom.db` 文件——**这就是你的全部业务数据（书、章节、规则、设置）**。

> ⚠️ 说明：`db:push` 内置 `--accept-data-loss` 参数。**全新安装无感知**；但以后升级新版本再跑它时，若新旧表结构有冲突性变更，可能删改旧数据——所以升级前先备份（见 [12.1 节](#121-升级三步走先备份) 与 [FAQ #9](#9-怎么备份数据怎么恢复)）。

✖ 常见报错：

| 报错关键字 | 原因 | 解法 |
| --- | --- | --- |
| `Error: SQLite database error` / `unable to open database file` | `db/` 目录不存在或无写权限 | `mkdir -p db data` 后重跑；仍不行 `sudo chown -R $(whoami) db data` |
| `Environment variable not found: DATABASE_URL` | `.env` 没配置好 | 回第 4 章重做 `cp .env.example .env` |

### 5.3 阶段自检

到这里，你的项目目录应该长这样（打勾核对）：

```text
novel-system/
├── db/custom.db        ✔ 刚生成（约几十 KB）
├── node_modules/       ✔ 刚生成（bun install 装的依赖）
├── .env                ✔ 你已编辑过
├── .env.example        ✔ 模板原件
└── src/ mini-services/ prisma/ ...  （项目自带）
```

## 第 8 章 认识 mini-services（8 个采集支撑服务）

### 8.1 它们是什么

主应用自带的采集引擎本身就能直连抓取大部分站点（HTTP 全功能）；但有些站点"只认浏览器"或"接口加密"，需要**同机的小帮手服务**做签名、解密、中继或隐身渲染。8 个服务、8 个固定端口（都只绑本机 127.0.0.1，**不要暴露到公网**）：

| 端口 | 服务 | 干什么 | 谁需要它（内置规则库 25 条中） | 不启动会怎样 |
| --- | --- | --- | --- | --- |
| 3010 | `bqg713-proxy` | 笔趣阁 bqg713 的 AES-token/解锁转换 | 「笔趣阁bqg713」1 条 | 仅该站采集失败，其余不受影响 |
| 3011 | `fetch-relay` | bun TLS 指纹中继（node+出口代理场景的出路） | 引擎自动按需调用，通用增强 | 引擎自动走 curl 链，多数站无感 |
| 3012 | `scrapling-bridge`（Python，可选） | 隐身抓取三模式（curl_cffi / 反检测浏览器 / 裸渲染） | CF 强防护站的可选备用路径（如霹雳书屋场景） | 引擎走内置 Obscura 渲染或其他链 |
| 3013 | `qimao-proxy` | 七猫官方 API 逐请求双签名 + 正文 AES 解密 | 「七猫官方API」1 条 | 仅该站采集失败 |
| 3014 | `deqixs-proxy` | 得奇正文三参数动态签名 + GBK 解码 | 「得奇小说网」1 条 | 仅该站正文失败 |
| 3015 | `xjp-proxy` | 新键盘正文双层 var c 解密 | 「新键盘小说网」1 条 | 仅该站正文失败 |
| 3016 | `cloak-browser`（需 chromium 环境） | 独立的 puppeteer 反检测浏览器服务（puppeteer-extra stealth 三档隐身；管理端健康页将它列为可选监控项，当前采集引擎未把它接入自动降级链） | 极难啃的 hard-WAF 站可作独立增强工具；内置 25 条规则均不依赖它 | 不启动无任何影响 |
| 3017 | `qidian-proxy` | 起点中文（镜像 API）目录解码 + 正文转换 | 「起点中文」1 条（正文还需 `QD_YWKEY`/`QD_YWGUID` 凭证） | 仅该站目录/正文失败 |

**结论：主应用不启动任何小服务也能正常跑**——内置 25 条规则里只有上表 5 条站点规则依赖对应代理，其余 20 条（77读书、番茄、知轩藏书等）完全不需要。对应站点规则的任务在代理缺席时会失败/降级，等代理启动后重跑任务即可。

### 8.2 怎么启动

**方式 A（试用模式自动启动）**：第 6.1 的 `bash .zscripts/dev.sh` 会自动把 8 个服务全部拉起（scrapling 桥缺 Python 环境时启动失败，无害，日志在 `.zscripts/mini-service-scrapling-bridge.log`）。

**方式 B（生产模式手动启动需要的那个）**：每个服务一条命令，在项目目录执行：

```bash
# 例：启动 3010 bqg713 代理（Bun 系服务通用格式：cd 进目录 + bun run start）
cd mini-services/bqg713-proxy  && bun run start && cd ../..

# 其余同理（目录名 = 服务名）：
#   mini-services/fetch-relay      → 3011
#   mini-services/qimao-proxy      → 3013
#   mini-services/deqixs-proxy     → 3014
#   mini-services/xjp-proxy        → 3015
#   mini-services/cloak-browser    → 3016（用 bun run dev 启动，需本机有 chromium）
#   mini-services/qidian-proxy     → 3017
```

> 💡 开发调试可用 `bun run dev`（文件改动热重启）；长期运行用 `bun run start`。`3017 qidian-proxy` 的正文凭证：在它的目录以 `QD_YWKEY=<key> QD_YWGUID=<guid> bun run start` 启动，未配置时三段发现照常、正文采集为空。`3012 scrapling-bridge` 是 Python 服务，安装步骤见其目录内说明（`mini-services/scrapling-bridge/package.json` 描述字段），属可选增强。

**方式 C（Docker 部署）**：5 个 Bun 代理（3010/3011/3013/3014/3015）**已随主容器自动共置启动，零配置**；scrapling 桥需要显式 `--profile stealthy`（见 DEPLOY.md 第四节）；3016/3017 不在容器内，需要时在宿主机按方式 B 启动。

### 8.3 怎么知道它们活着

后台**仪表盘 → 服务健康灯**（绿=在线）就是逐个探测这些服务的 `/health`；也可以手动验证：

▶ 执行：

```bash
curl http://127.0.0.1:3011/health
```

✔ 你会看到（示意）：

```text
{"ok":true,"runtime":"bun"}
```

✖ 灯是红的 / curl 连不上：见 [FAQ #13](#13-仪表盘健康灯有红的或-mini-service-连不上)。

> ⚠️ **安全**：这 8 个服务默认只绑 127.0.0.1（仅本机可访问），**不要**主动把它们映射/暴露到公网。多主机分离部署才需要设 `BRIDGE_KEY` 共享密钥（见 DEPLOY.md「二·五」）。

```
│ ☑ 自动增量续采  任务完成后每 [30] 分钟自动补采连载新章节        │

```

| 向导字段 | 新手怎么填 |

| --- | --- |
| `http://host:port` | HTTP 代理 |

## 第 11 章 常见问题 FAQ（16 条速查）

每条格式：症状 → 解法（复制粘贴即用）。更深的运维问题见 [DEPLOY.md](../DEPLOY.md)「三、常见问题 FAQ」。

### #1 端口 3000 被占用了怎么办

查谁占用了：

```bash
lsof -i :3000        # 没有 lsof 就用: ss -ltnp | grep 3000
```

- 是自己之前起的旧进程 → `kill 那个PID` 后重启；
- 想换端口：本机直跑见 `package.json` 的 `dev`/`start` 脚本与 next 启动参数；**Docker 部署**编辑 `docker-compose.yml` 把 `ports` 的 `"3000:3000"` **左侧**改成空闲端口（如 `"8080:3000"`）后 `docker compose up -d`，用 `http://IP:8080` 访问。

### #2 服务器 curl 得通但浏览器打不开

云服务器**安全组**或系统防火墙没放行 3000：厂商控制台 → 安全组 → 添加"TCP 3000 允许"；系统防火墙 `sudo ufw allow 3000/tcp`。地址别漏端口 `http://IP:3000/`。

### #3 忘记后台密码怎么办

密码只来自 `.env`（或 Docker 的环境变量）里的 `ADMIN_PASSWORD`，**没有**存在数据库里。直接改它然后重启即可，**不需要旧密码**：

```bash
nano .env                # 把 ADMIN_PASSWORD= 换成新密码
# Docker: docker compose up -d 重建生效
# 本机直跑: 重启 bun run start
```

（Docker 用户也可以在 `docker-compose.yml` 的 `environment:` 段写 `- ADMIN_PASSWORD=新密码`，效果相同。）

### #4 登录后过一会儿又要重新登录 / 登录一直失败

- 会话有效期 **12 小时**，到期重新登录是正常设计；
- 登录一直失败：密码不对（对照 #3 的来源查），或浏览器禁了 Cookie（本站登录依赖 Cookie，允许即可）；
- 改过 `ADMIN_PASSWORD` 后旧会话自动失效，用新密码登录即可。

### #5 数据库报错 database is locked / SQLITE_BUSY

SQLite 是单文件数据库，同一时间只应有一个进程在写。最常见原因：**起了两份服务共用同一个 `db/custom.db`**（比如 dev 和生产同时跑、或两个终端各起了一份）。解法：停掉多余的进程只留一份；仍偶发时可重跑任务（引擎对数据库写失败有自动重试）。改表结构前先备份数据库文件。

### #6 采回来的正文乱码（GBK 站）

引擎已内置 GBK 等编码自动识别，正常无需配置。仍乱码时按序排查：① 该规则走了代理 → 先绕开代理验证（代理转码是乱码最常见来源）；② 只有该站乱码 → 到规则编辑器「内容清洗」页签看是否有适配性清洗规则可调；③ 对照同类杰奇系站点规则（如内置的飘天文学是 GBK 直连站）的配置抄作业。

### #7 采集大量 403 / 429 / 被封

降线程、拉大间隔（慢速档起步）；用规则页的「校准」实测该站安全参数（见 DEPLOY.md 第六节）；"只认国内 IP"的站按 9.4 配出口代理；尊重目标站 robots 与服务条款，控制频率合规采集。

### #8 Docker 命令报 permission denied

```bash
sudo bash install.sh               # 临时方案
sudo usermod -aG docker "$USER"    # 长期方案：加入 docker 组
# 加入组后退出重新登录才生效
```

### #9 怎么备份数据怎么恢复

两种方式：

- **后台一键**（推荐）：后台 → 数据备份 → 导出（下载 JSON 文件）；恢复用同页「导入」；
- **文件级**：停服后整体拷贝 `db/` 与 `data/` 目录：

```bash
docker compose down          # Docker 用户先停（保证 SQLite 落盘一致）
cp -r db data /你的备份路径/
docker compose up -d
# 恢复：把目录放回原位再启动；换过服务器记得 sudo chown -R 1001:1001 ./db ./data（Docker 非 root 容器需要）
```

### #10 构建或安装中途，日志出现 `Killed`

内存不足被系统杀（构建峰值超 2 GB）。解法：加大内存到 4 GB 重跑；或临时加 2 GB swap（通用 Linux 技巧：`sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`）后重跑；或改走 Docker 路径。

### #11 仪表盘健康灯全绿，但前台书城是空的

还没有采到任何书：到「采集任务」页看有没有任务在跑/已完成；没任务就按第 9 章建一个；Docker 自动填充用户看 `docker compose logs -f | grep 自动填充`，首采约 20~40 分钟。

### #12 怎么加一条自己的规则？

三条路（由易到难）：① **内置规则库**导入最接近的现成规则再「编辑」微调；② 规则页工具栏「模板库」从预置模板起步；③ 「新建规则」从零手写——四段各填选择器/正则，逐段用右列测试面板验证后再保存。字段语义与取值极限见 `docs/rule-limits.md`。

### #13 仪表盘健康灯有红的，或 mini-service 连不上

- 先确认你**是否真的需要**那个服务（对照第 8 章表格，红的不在依赖清单里就无所谓）；
- 需要的话：进对应目录手动 `bun run start` 看报错；试用模式看日志 `.zscripts/mini-service-<服务名>.log`；
- 端口被占用：`lsof -i :301x` 查占用者；
- Docker 用户：3010/3011/3013/3014/3015 由入口脚本自动拉起（看 `docker compose logs` 里 `[代理]` 行）；3012/3016/3017 不在容器内，需宿主机自启。

### #14 自动填充没书 / 想关闭或换站点

- 关闭：Docker 路线 `AUTO_FILL=0 bash install.sh`（或编辑 docker-compose.yml 的 `AUTO_FILL` 后 `docker compose up -d`）；
- 换站点：`AUTO_FILL_RULES=fanqie,qimao bash install.sh`（可选 key：fanqie / qimao / deqixs / 80ge / jhssd / ttkan / bqg713 / pili* / xjp*，带 * 的默认不参与：pili 需隐身渲染增强、xjp 体量大）；
- 本机直跑路线没有自动填充（那是 Docker 引导脚本的功能），手动按第 9 章建任务即可。

### #15 出口代理填了但还是 timeout

- 先在本机验证代理本身可用（通用技巧）：`curl -x http://user:pass@host:port 目标站`；
- 代理出口不是真·国内 IP，或已被目标站风控 → 换代理；
- 403/验证码页：该代理 IP 被盯上，换代理或保持低频。

### #16 怎么把 3010~3017 暴露出去给别的机器用？

**不要**。这些服务是设计成"仅本机回环"使用的开放代理介质，暴露公网有被滥用的风险。确有多机需求：设 `BRIDGE_KEY` 共享密钥并自行做好网络隔离（见 DEPLOY.md「二·五」；注意引擎当前不主动发送该头，跨机部署前请先阅读该节说明）。单机部署什么都不用做。

## 第 12 章 升级 / 更新 / 卸载

### 12.1 升级三步走（先备份）

无论哪种部署方式，升级前**先备份**（FAQ #9）。

**本机直跑（Bun）路线：**

```bash
cd ~/novel-system
git pull                 # 拉新代码（压缩包部署的用新包覆盖目录）
bun install              # 依赖可能有更新
bun run db:push          # 数据库结构增量同步（升级前已备份！）
# 然后重启：
#   Ctrl+C 停掉旧 bun run start → bun run start 重新起
#   或 kill 掉旧进程后重新构建：bun run build && bun run start
```

**Docker 路线（更省事）：**

```bash
cd ~/novel-system
git pull
bash install.sh          # 幂等：自动重建镜像与容器，数据不受影响
```

- 升级只替换程序，`db/`、`data/` 数据不受影响；
- 若新版本改了表结构：本机路线 `bun run db:push` 会增量同步；Docker 路线容器首启自动同步（刻意不带 `--accept-data-loss`，绝不静默毁数据；冲突时日志会给中文指引，见 DEPLOY.md FAQ 第 4 条）；
- 升级后记得重新启动你手动拉起的 mini-services（第 8 章）。

### 12.2 更新代码后的小服务

`git pull` 不会自动重启正在跑的 mini-services：手动把用到的那几个 `kill` 掉再 `bun run start`；试用模式直接重跑 `bash .zscripts/dev.sh` 全家桶。

### 12.3 卸载

**本机直跑：**

```bash
# 1) 停服务（kill 掉 bun run start / dev 进程与用到的 mini-services）
# 2) 备份想留的数据（FAQ #9）
# 3) 删整个项目目录
rm -rf ~/novel-system
# 4)（可选）卸载 Bun：rm -rf ~/.bun
```

**Docker：**

```bash
docker compose down --rmi local   # 停容器并删除本机构建镜像
# 数据仍在 ./db ./data —— 彻底删除连目录一起删：
# sudo rm -rf db data
```
